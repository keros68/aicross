# TASK-89 桌面端补派发设置入口，并修配置的不便之处

## 问题

1. 派发设置（`~/.aicross/dispatch-settings.json`）只能用 `aicross config set` 命令行改，桌面端五页里没有任何入口。用户最常见的疑问「并发上限 3 在哪改」无处下手。
2. 各设置的合法区间（并发 1–3、超时 1–3600 秒、修正轮 0–3 等）只存在于代码与夹取逻辑里；命令行越界写入会静默夹取，桌面端用户连区间都看不到。
3. 超时以秒为单位（600、1800），与用户心智里的「10 分钟、30 分钟」不一致。
4. 设置文件路径（含 `AICROSS_HOME` 覆盖）桌面端不可见，出问题要自己找文件。

## 要做

1. Rust 侧（`src/console_cli.rs`、`src/server.rs`）：
   - 从 `run_config_set` 抽出共享实现 `config_set_at(root, patch, acp)`：接受一组键值（JSON 值），沿用现有键名校验、夹取、取整提示与合并写入；CLI 输出与退出码不变。
   - 新窗口命令 `dispatch_settings`：返回当前设置、设置文件路径与 ACP 适配器状态，不经主 agent 解析（派发设置不分主 agent）。
   - 新窗口命令 `dispatch_save(patch)`：走 `config_set_at`，返回写入后的设置、夹取说明与（开启 ACP 时的）适配器安装结果；设置已写入、仅适配器装不上时不算失败，说明原样带回。
2. 前端（`src-ui/`）：
   - 顶栏加「设置」入口（图标按钮），弹出的对话框一页改完派发设置：并发上限（1–3 分段）、同时派发上限（1–3 分段）、单次派发上限（1–100）、修正轮上限（0–3 分段）、蜂群上限（1–4 分段）、三个超时（按分钟，1–60）、脱敏、派发记录写进项目目录、验证命令、ACP 开关（附适配器状态一行）。改动收进草稿，点「保存」一次写入。
   - 超时按分钟显示与输入（600 秒显示 10），保存时换算回秒；数值输入越界或非数字时给出说明并停用「保存」。
   - 对话框底部注明设置文件路径。
   - 设置的展示与校验逻辑拆纯函数模块并补单元测试；窗口命令参数进现有 tauri-commands 测试。
3. 文档（`docs/MANUAL.md`）：派发设置一节补桌面入口说明。

## 不做

- 不放宽并发上限 3 的夹取（本期只补入口，上限本身是产品决定）。
- 不给 `dispatch-settings.json` 加进程间写锁：窗口与命令行同时写的窗口极小，与现状一致。
- 设置文件损坏时不自动覆盖（与命令行一致，保存失败原样显示说明）；ACP 之外的文本设置（ccSwitchPath、分类模型）仍走命令行。
