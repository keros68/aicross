# TASK-76 派发在宿主对话里只留要做决定的内容

## 问题

`dispatch.py` 的输出同时写给三个读者：用户、宿主模型、事后复查。全部进了宿主对话。2026-11-13 一次两家盲审的宿主会话记录（Claude Code，东北森林带项目）：

| 位置 | 实际情况 |
|---|---|
| 方案输出 | 9 行，用户要看的只有 2 行路由与 1 行外发说明，其余是写给模型的操作提示 |
| 各路回答 | 两路全文 7,046 字整段进上下文；上限是每路 12,000 字 |
| 收尾小结 | 1,900 字，路由行原样重复一遍，独立性、账单、记录每次各占一行 |
| 等待 | 「正在等两家审查回来」说了 3 次；兜底定时检查在结果汇报完之后又触发一条重复消息 |
| 重复提示 | 「.dispatch 没有迁完」同一次打印两遍；「还没检查过新模型」每次派发都出 |

另一件事：2026-11-14 一路超时 480 秒，整次派发等了 8 分钟；下一次选人仍会先选到它。

## 范围

只改 `skills/ai-cross/`（`references/dispatch.py`、`references/inventory.py`、`SKILL.md`、`references/rules.md`、`references/channels.md`、`README.md`、测试）与 `docs/PRODUCT.md` 的对应条目，改完运行 `python scripts/sync-skill.py`。引擎 `src/` 不动。

1. **开场一次派发一行**：`- [ai-cross] 盲审 → <厂商 模型（经 程序）>、… ｜ <档位> · thinking=<…> ｜ 材料 <名称>，<大小>`。选人理由只在宿主厂商不确定时显示；脱敏、按次计费、未冒烟照旧以「注意」行显示。给模型的操作提示合成一行。
2. **各路回答只显示「会出错」**：`review --go` 每路打印开头段（至多 600 字，没运行、没做完的说明在这里）与「会出错」一节；「建议」只报字数，整篇在记录里。回答没按两节写时整篇打印；`--full` 强制整篇。`run --go` 的回答是产出本身，照旧整篇打印。
3. **小结骨架只留要拍板的事、未验证与一行脚注**：脚注写谁审的、独立与否、耗时、记录目录。路由回显、独立性单列、账单从输出里去掉，这些都在记录的文件头里。各路都没有结果时不给骨架。
4. **提示降噪**：旧记录迁移每个进程每个项目只做一次；检查新模型的提醒不进派发输出，留在 `show` 与 `pick`。
5. **失败排后**：一路超时、出错或真身不符时，在 manifest 该条目记 `last_failure`；一天内选审查者时排到后面并在「注意」里说明，成功一次即清除。不改冒烟状态，点名不受影响。
6. **外发的同意**（2026-11-15 用户定）：用户自己发起并点明了材料的只读派发，这句话就是同意，给出开场一行后直接发。skill 提议的派发、经引擎且会改项目文件的模式、超出用户所指的材料、按次计费、不算独立的审查，仍等用户同意。
7. **等待只说一次**：后台运行时对用户说一次「已派出」，结果回来前不重复、不另设定时检查。

## 不做

- 不改审查默认的思考强度。原打算从高降到中；核对后发现 pi 下部分模型只支持关、高、最高三档（如 `deepseek-v4-pro`），降到中会让这一路直接报错。
- 不合并 skill 的入口命令，不统一 `dispatch.py` 与 `aicross dispatch` 的参数名（牵涉引擎，另起一期）。
- 不给没装引擎的用户补记裁决。
- 不按计费来源连带排后（同一订阅下的其他条目）。
- 不 push，不改应用版本号。
