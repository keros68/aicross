# Pi 流式派发与超时处理

用户要求排查 pi 调用超时，修好后继续用 DeepSeek 与 GLM 核对预算工作簿。

范围：`skills/ai-cross/references/dispatch.py` 的 Pi 子进程调用及相应测试；同步内置 skill 包。不改凭据、代理、模型默认值，不发布或提交远端。

观察：短请求两模型分别约6秒、1.5秒成功；140KB高思考请求在90秒内持续返回五千余个流式事件。当前Pi 1.3已压缩增量，缓存不是本次生成耗时的主要来源。两个指定模型的medium均不受支持，会被Pi自动向上取high；默认输出上限为384000/131072，持续思考未及时收尾。Windows命令包装层在600秒超时后仍有后代持有管道，实际返回被延迟。

完成条件：读取时过滤Pi更新（兼容携带累计内容的旧版），保留最终正文、身份及用量；超时有界地停止整个进程树并保留已收到的必要事件；阻止不受支持的思考档位静默提升，拒绝length/aborted输出；保持冻结盲审模板和隔离参数；真实子进程测试通过，并用受控输出上限的项目入口继续预算复核。大材料拆成独立小批次。输出上限及已加载的受控扩展须记录，不将截断视为通过。
