**只改 `src/channels/mod.rs`（额度分类与恢复时间解析及其测试）。不 commit，不 push。**

## 问题

10-01 真机：经 pi 派给智谱 coding plan（`zai-coding-cn/glm-5.3-flash`）撞 5 小时上限，节点正文是：

```
429: {"code":"1308","message":"已达到 5 小时的使用上限。您的限额将在 2026-10-01 13:30:41 重置。"}
```

`classify_quota` 没认出来，节点记成普通 `failed`，不会触发「额度用尽 → 切备选 / 标恢复时间」。原因：

- 开头的 `429:` 前面没有 `http` / `status` / `code` 前缀，状态码正则不匹配；`"code":"1308"` 引号夹在 `code` 与冒号之间，也不匹配。
- 中文规则要求同一句里同时有「额度 / 限额 / 配额」与「用尽 / 不足 / 已达 / 超出 / 耗尽」；第一句只有「已达到 … 使用上限」，第二句只有「限额 … 重置」，两句都凑不齐。
- 恢复时间是不带时区的本地时间 `YYYY-MM-DD HH:MM:SS`，`parse_quota_reset` 没有对应解析。

## 要求

1. `classify_quota` 认出这类响应：中文规则补「使用上限 / 用量上限 / 达到上限」一类表述（「已达到 … 上限」），以及「限额 / 额度 将在 … 重置」；文本开头或独立出现的 `429:` 视同 429 状态。不放宽到会误判普通报错：补反例测试（例如正文里只是讨论「上限」一词、`1429` 这类数字、「重置密码」之类不相关的文本都不判额度）。
2. `parse_quota_reset` 解析「将在 YYYY-MM-DD HH:MM:SS 重置」这类不带时区的时间，按本机时区（`Local`）解释，输出 RFC 3339；时区处理与现有 `CLOCK` 分支一致。
3. 补测试：上面那条原文 → `QuotaHit { reason: "rate_limit" 或 "quota"（说明取哪个与理由）, resets_at: Some(..) }`，恢复时间解析正确；现有全部额度分类测试照常通过。新测试在修复临时改回时必须变红。
