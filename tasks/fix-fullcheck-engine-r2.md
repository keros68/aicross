# fix-fullcheck-engine 第二轮

来源：Codex（gpt-6.1-sol）对第一轮修正的只读复审，结论「修后合并」。范围、验证与规矩同 `fix-fullcheck-engine.md`。

## 要改

1. **（P1）自写锁文件不能保证互斥**：`src/file_lock.rs` 的过期接管与「读令牌 → 删除」释放都有竞态（两个等待者同时接管；释放与接管交错误删新锁）。改用标准库的系统文件锁：`std::fs::File::lock()` / `try_lock()`（Rust 1.89 起稳定，本机 rustc 1.97.1）。锁随文件句柄释放，进程崩溃时由系统释放，不再需要过期接管与令牌；等待用 `try_lock` 轮询加超时。锁文件本身可以常驻、不删除（删除会重新引入竞态）。资源库锁与 skill 安装锁都改用它；删掉不再需要的过期与令牌逻辑及其测试，补「两个持有者互斥」「持有者句柄关闭后另一方立即拿到」「超时返回错误」测试。这同时解决复审第 3 条（无法移走的过期锁导致无限循环）。
2. **（P1）安装残留仅凭名称前缀删除，恢复未排除链接**：
   - 暂存目录里的新格式残留：写入时在残留根目录放一个小记录文件（目标路径、操作令牌），清理与恢复只认带记录且目标路径与本次一致的；没有记录或对不上的保留，在返回结果里提一句。
   - 旧格式残留（skills 目录及其上一级里的 `.aicross-install-tmp-*` / `-bak-*`）：只在目录里有我们的安装标记文件时才删或恢复；没有标记的保留。
   - 恢复前拒绝残留根目录与内容目录是 symlink / junction 的情况（保留，不恢复、不删）。
   - 补测试：无关同名前缀目录不被删、链接残留不被恢复。
3. **（P2）Kimi 长提示词截断掉了如实汇报后缀**：一次性 Kimi 通道的 30,000 字节上限先给收尾句预留字节，截正文后再追加收尾；测试断言最终 invocation 的实际文本以收尾句结尾。
4. **（P2）后缀去重篡改原始材料**：`with_closing` 不再对全文 `replace`。只在引擎自己拼的收尾部分里保证收尾句出现一次（例如：最终文本若已以收尾句结尾就不再追加；否则追加），用户原文、diff、内联源码原样保留。补测试：材料里引用了收尾句原文时，材料不被改动。
5. **（P2）报告事实错误**：`src/main.rs` 在 HEAD 与工作树都是 CRLF（复审直接读 blob 核实：279 / 280 个换行全为 CRLF），更正报告；「12 条全部修复」改为如实写明第一轮的缺口与第二轮的修正。
