## 2. backlog 81：结论的「轮」与多分支判定

现在按验收行去重 stage 数计「轮」，两个偏差：
- 两条不等深的并行验收分支，浅分支最后一次 NEEDS_FIX、深分支 PASS 时，只看最大 stage 会判「通过」。
- 预设本身带多个验收阶段（不是修正轮生成的）时，措辞会写成「修正 N 轮后」。

改为：
- **判定**：取每条验收链的**最后一次**验收结论（该验收节点之后同链上没有更晚的验收节点）；任一链最后一次是 NEEDS_FIX → 未通过；否则任一非 PASS → 无法识别；全 PASS → 通过。
- **轮数**：按本次运行实际生成的**修正执行节点**数计（TASK-29 的 `fixRoundNodeIds` 范围内），没有修正就不写「修正 N 轮后」。
- 措辞示例：「通过（验收一次通过）」「通过（修正 1 轮后通过）」「未通过（修正 1 轮后验收仍要求修正，已到上限）」。
补测试：不等深两分支、预设自带两个验收阶段无修正、一轮修正后通过、到上限未通过。至少一格走 `createConsoleApplyHandler` 真实接线。
