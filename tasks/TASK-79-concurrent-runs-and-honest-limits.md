# TASK-79 并发派发不冲突，说明与实际能力一致

## 问题

TASK-78 的盲审里留下三类没处理的问题，核实后：

| 位置 | 实际情况 |
|---|---|
| 派发目录、临时目录 | 都只按秒命名。宿主在一条消息里并行发两条派发命令时落在同一秒：同一条目会因目录已存在而报错，先结束的一方会删掉另一方还在用的目录，记录写进同一个目录 |
| 记录文件名 | 只含程序名与模型名。同一模型经两个 provider 同时被选中时，后写的覆盖先写的 |
| `manifest.json.tmp` | 两条命令共用一个临时文件名 |
| `claude` 通道 | 探测时已发现 `ANTHROPIC_BASE_URL` 被改写，但保存时仍按模型名认定厂商是 Anthropic |
| 说明文字 | 写「真身核对由脚本做」，实际只有 pi 通道核对；写「执行者没有工具、看不到项目文件」，2026-11-15 真机上 codex 与 kimi 都读到了目录外的文件 |
| 条目名 | 纯中文的名字规范化后为空，之后派发时报错 |
| `smoke` | 选中的条目全被跳过时退出码为 0 |

## 范围

只改 `skills/ai-cross/`，改完运行 `python scripts/sync-skill.py`。

1. 派发目录由 `claim_run` 原子地占用，同一秒的第二条命令得到 `<时间>-2`；临时目录名加进程号。
2. 同一次派发里两路的程序名与模型名都相同时，记录文件名带上条目名。
3. manifest 的临时文件名加进程号。
4. `claude` 被重定向时，保存必须写明 `vendor`，不拿模型名比对。
5. `SKILL.md`、`channels.md`、`run` 的方案与收尾文字按通道如实说明：pi、claude 没有工具；codex 只读沙箱，读得到本机文件；kimi 没有只读档。真身核对写明只有 pi 自动做。
6. 条目名为空时拒绝保存；`smoke` 没有任何条目被实际测到时退出码 1。

## 不做

- manifest 不加跨进程锁：两条命令同时写时后写的仍会盖掉先写的那一次冒烟日期或失败标记。
- 不给 codex、kimi 找禁用读取的参数。
- 不给 pi 以外的通道加真身核对：这些命令行不返回实际应答的模型名。
- agy 大材料与「不要使用任何工具」的提示冲突：本机没有 agy。
