# TASK-02 方案与编排：阶段条、节点面板、表单构建器、预设、讲解页

先读 `AGENTS.md`、`docs/PRODUCT.md`（「三个引擎、两个开关」「模式清单」「自定义工作流」三节）、`tasks/REPORT-00.md`、`tasks/REPORT-01.md`。原型 `docs/proto/index.html` 的右栏是形态基准。本期只做**编排的数据模型与界面**，不执行任何派发（第 3 期）。

## 数据模型（定了就是契约，后续期不改字段名）

```
Workflow { id, name, builtin: bool, stages: Stage[] }
Stage    { nodes: Node[] }                       // 同阶段并行，阶段间串行
Node     { agent, provider?, model, role, tier?, thinking, visibility, write }
role       = 出方案 | 执行 | 验收 | 验证 | 自定义文本
thinking   = 关 | 低 | 中 | 高（映射到各 CLI 的实际参数在第 3 期做）
visibility = 共享 | 盲 | 指定上游（上游节点 id 列表）
write      = 只读 | 单写者 | worktree
```

- 角色默认值：`执行`/`出方案` → visibility=共享、write=只读；`验收`/`验证` → visibility=盲、write=只读。用户可改。
- 模型只能从 `resources.json` 里 **status=已接入** 的条目选；条目消失或变为未接入时，节点显示"模型不可用"但不删。
- 持久化 `~/.aicross/workflows.json`：`{ version: 1, workflows: [...] }`。内置三个（`builtin=true`，不可删可复制）：
  - **共享对话**：一段一节点，role=执行，visibility=共享。默认预设。
  - **经济流水线**：`出方案(高档,thinking=高) → 执行(低档,thinking=低) → 验收(盲,换厂商)`，三段各一节点，模型留空由用户填。
  - **盲审**：一段三节点，role=验证，visibility=盲，write=只读。
  - 擂台 / 评审团 / 仲裁 / 前提抽查 / 主备 / 顾问 / 红蓝 / 群聊 / 蜂群 在预设下拉里置灰并标期次，不实现。

## 一行记法（与表单双向同步）

```
fable-5 → [gpt-5.6-terra | k3 | glm-5.2]@blind → glm-5.3
```

- `→` 分阶段，`[a | b]` 同阶段并行，后缀：`@blind`（盲）/`@shared`（共享）、`#off|#low|#mid|#high`（thinking）、`:ro|:rw|:wt`（写权限）、`!role`（角色，如 `!验收`）。模型名可写 `agent/model` 消歧，省略 agent 时按 resources.json 唯一匹配，不唯一则报错指出候选。
- 实现 parser 与 printer，**往返测试**：任意合法 Workflow → 一行 → 解析 → 与原 Workflow 相等；错误输入给出位置与原因（中文）。

## 界面（右栏「方案与编排」tab）

1. 顶部预设下拉（内置 + 用户保存的），选中即把该工作流装入阶段条。
2. **阶段条**：竖向或横向列阶段，每阶段内节点并排；节点卡显示 `agent/model · 角色 · 档位 · thinking · 可见性/写权限` 缩写；点节点弹出**节点面板**改各字段（模型下拉只列已接入）。
3. 「编辑编排」打开**构建器**：阶段按行，行内「添加节点」「删除节点」，行间「添加阶段」「删除阶段」「上移/下移」；底部同步显示一行记法（可编辑，失焦时解析回表单，解析失败红字提示不覆盖表单）；按钮「保存为预设」（要名字）「应用」「关闭」。
4. 中栏输入框上方一行"当前方案：<预设名> · N 段 · M 节点"，点击切到右栏。
5. **校验提示**（不阻止保存，只标注）：验收/验证节点的 vendor 与同工作流任一执行/出方案节点 vendor 相同 → 节点上标"复核，非独立验证"；盲节点的上游若为共享 → 无提示（合法）；节点模型未接入 → "模型不可用"。
6. 「讲解」链接：打开独立视图（全屏覆盖层），按预设分节：一句定义 + 步骤列表 + 两个开关的含义。内容从 `docs/PRODUCT.md`「模式清单」「三个引擎、两个开关」抽，保持说明体。
