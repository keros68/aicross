# TASK-69 模型的使用记录与用途标签

用户 10-30 定：让「谁擅长什么」从用户自己的派发记录里得出，派发前用上；不维护在线排名，不自动改配置。

现状：派发记录（`runs/`）30 天后删除；窗口的「采纳」几乎没人点（本机 15 次派发，采纳 0 次），裁决都在宿主对话里。所以统计不靠采纳，靠引擎自己产生的信号，并单独长期保存。

## 要做

1. **任务类型**：`aicross dispatch` 加可选 `--kind <类型>`。类型是固定小表：前端 `frontend`、后端 `backend`、文案 `writing`、数据分析 `data`、文档 `docs`、其他 `other`；中文名与英文 id 都认，别的值退出 2 并列出可选值。记进 run 文件 `task_kind`；不给为空（统计里算「未分类」）。
2. **结果记录**：每次派发在后台跑完（成功或失败）时，按最终的图给每条执行链追加一行到 `$AICROSS_HOME/track/outcomes.jsonl`，不随 `runs/` 删除。执行链 = 第一轮执行节点加它后面的修正轮。结果分：
   - 一次通过：第一轮的验收结论为 PASS；
   - 修正后通过：修正轮后的验收为 PASS；
   - 未通过：验收到顶仍要求修正，或验证命令到顶仍未通过；
   - 失败：执行本身出错、超时、真身不符、额度用尽；
   - 无验收：执行完成但这个模式没有验收位置；
   - 结论不明：有验收但结论读不出（验收位置自己失败等）。
   叫停的、从没跑过的、切了备选的执行链不记。只记执行位置；出方案、验收、验证的质量没有可靠信号，不记。
3. **采纳**：`aicross adopt` 成功时追加一行采纳记录（同一节点只算一次）。skill 在用户于对话里认可某一路时调 `adopt`。
4. **用途标签与备注**：`$AICROSS_HOME/model-notes.json`，按 `agent:provider:model` 存一行备注和若干标签（标签取任务类型表）。命令 `aicross resources note <agent>:<provider>:<model> [--tags 前端,文案] [--note 文本]`；不给选项时显示当前值，`--tags ""` 清空标签，`--note ""` 清空备注。不放进 `resources.json`，重新探测不影响它。
5. **汇总**：`aicross stats [--kind <类型>]` 输出 JSON：每个模型的标签、备注、按任务类型的次数与各结果数、采纳数；`judged`（有验收结论的次数）不少于 5 时给通过率，少于 5 只给次数。每个类型另给 `ranked`（样本够的模型按通过率排序）与 `tagged`（标了这一类的模型）。
6. **窗口**：资源页每个模型行显示标签与一行记录（如「前端 · 7 次 · 一次通过 5」）；「标注」按钮就地改标签与备注。
7. **skill**（`skills/ai-cross/references/channels.md`「按窗口配置派发」）：
   - 派发时按任务内容带 `--kind`，拿不准就写 `other`；
   - 派发前跑 `aicross stats --kind <类型>`：执行位置的人选在这一类上样本够且通过率比另一个可用模型低 20 个百分点以上，或人选没标这一类而有可用模型标了，开场后加一行提示，用户同意才用 `--seat` 只换这一次；
   - 有多种做法、要挑一个的任务（界面方案、命名、写法取舍），默认模式不是擂台模式时提一句可以用擂台模式；
   - 用户在对话里认可某一路的结果时调 `aicross adopt`。
   改完跑 `python scripts/sync-skill.py`。
8. 文档：`docs/MANUAL.md` 命令表与术语表、`docs/CONSOLE-CHANNEL.md`（`--kind`、`task_kind`）、`docs/PRODUCT.md`（本期落地，移出「已采纳、未排期」的「模型备注与用途标签」）。

## 不做

- 不用统计结果自动改人选，一键推荐暂不读它。
- 不补算旧派发（旧记录没有任务类型）。
- 不做费用与额度统计。

## 完成条件

- 单元测试：任务类型解析；六种结果的判定（含修正轮、验证重试、叫停与备选不记）；采纳去重；标签读写与清空；汇总的通过率门槛与排序；`--kind` 进 run 文件。
- `cargo test`、前端 `npm run build` 与前端测试通过。
- 命令行实跑 `resources note` 与 `stats`。
