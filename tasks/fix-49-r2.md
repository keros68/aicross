# fix-49-r2 层次与区分（用户 10-06 真机反馈）

用户看了 r1 的窗口：「感觉很单调，模块之间得处理下」。现状：所有卡片同一形态（灰色单字图标块 + 名称 + 一行灰字），页面之间、模块之间没有层次。参照仍是 CC Switch 两张截图（见 fix-49-r1.md），尤其是用量统计页的「顶部数字卡 + 图表区 + 下方明细」分层，以及供应商列表里各家带颜色的标识。

本轮只改外观与信息组织，命令与数据流不变；不新增需要后端支持的功能，所有数字都从已有数据算出。

## 1. 页顶概览卡（三页都有）

页头下方一排 3–4 张数字卡（参照用量统计页「总成本 / 总请求数 / …」：小灰字标签 + 大号数字，白底卡片），数字从已有数据算：

- 资源：agent 数 · 可用模型数 · 已验证数 · 需处理数（未发现 + 验证失败 + 未登录；为 0 时数字用常规色，非 0 用异常色）。
- 模式：默认模式名 · 已配好的模式数 / 模式总数（所有位置都有有效人选算配好）· 未指定或失效的位置数。
- 派发记录：最近记录数 · 已完成 · 失败 · 进行中。

## 2. 模式页分组与流程表达

- 分三组，每组一个小节标题（灰色小字 + 细分隔线）：「常用」（经济、盲审、共享）、「更多模式」（擂台、评审、蜂群）、「自定义」（`builtin` 为 false 的；没有就不显示这组）。
- 每个模式有自己的线框图标与浅色底标识块（替代单字），颜色按模式区分、低饱和、两种主题都可读，例如：共享 蓝、经济 绿、盲审 紫、擂台 橙、评审 青、蜂群 琥珀、自定义 灰。颜色作为变量定义在 `global.css`（两套主题各一份）。
- 人选摘要改成「流程条」：每个位置一枚小胶囊「角色 · 模型」，胶囊左侧一个厂商色点（复用 `viewer/vendor.ts`）；同阶段胶囊并排，阶段之间用「→」。未指定 / 失效的胶囊用异常色描边与文字。胶囊放不下时折行，不横向滚动。
- 默认模式那一行保持蓝色生效样式。

## 3. 资源页区分各家

- agent 标识块用厂商色（复用 `viewer/vendor.ts` 的色值做浅底 + 同色图标或首字母），不再一律灰色。
- 卡片副标题改成小统计：「12 个模型 · 3 已验证 · 2 需处理」，需处理非 0 时那一段用异常色。
- 展开后的模型列表按 provider 分小组（pi 有多个 provider 时有用），每组一个灰色小标题。

## 4. 派发记录

- 表格上方加分段切换「全部 / 已完成 / 失败」（参照「直连 / 路由 / 聚合」的样式），只在前端按状态筛选已有数据。
- 模式列前加该模式的标识色点，与模式页一致。

## 5. 一致性与约束

- 卡片之间、分组之间的间距分级：同组卡片 8px，组与组 24px，概览卡与下方内容 20px。
- 颜色只走变量；新增变量两套主题都定义。
- 视觉纪律其余条目照旧（厂商色与模式色都只做小面积标识：色点、标识块浅底、胶囊描边，不做大面积填充）。
- 纯函数补测试：三页概览数字的计算（含 0 与非 0 的着色判定）、模式分组、流程条的胶囊数据（含失效）、资源卡片的小统计与 provider 分组、派发记录筛选。

## 6. 自查

不要只靠测试：用你上一轮的办法（构建产物 + 注入假数据在浏览器里看），浅色与深色各看一遍三页，并对照两张 CC Switch 截图自问「看上去是不是同一类工具、页面之间有没有层次」。在回复里说明你看到的效果与仍不满意的地方。
