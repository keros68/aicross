# fix-fullcheck-ui 第二轮

来源：Codex（gpt-6.1-sol）对第一轮界面修正的只读复审，结论「修后合并」。范围、验证与规矩同 `fix-fullcheck-ui.md`。

## 要改

1. **（P1）迟回的写入响应覆盖新配置**：设默认等写入与人选写入可以并行，后发先回、旧的整份 `result.modes` 后回会把新人选盖回去。改为配置写入串行：`snapshot-sync` 的写入排队一个接一个执行；从第一个写入开始到最后一次统一重读完成，模式页保持编辑锁定（`editing` 把设默认、视角、数量、推荐等都算进去）；重读失败时保持提示并允许手动刷新。补测试：「后发写入先返回、旧整份响应后返回、重读延迟」。
2. **（P2）自定义模式保存、删除绕过写入协调**：编辑器保存与删除都经模式页同一个写入入口（`sync.write`），成功后统一重读，不再靠 `reloadKey` 事后纠正。补测试：保存 / 删除期间发起的读取不会落地旧快照。
3. **（P2）下拉展开后滚动或缩放仍会被裁切**：展开期间祖先滚动或窗口 resize 时关闭弹层（最简单、与常见下拉一致）。补测试（事件处理的纯函数部分；组件接线由 tsc / eslint 保证）。
4. **报告**：在 `tasks/REPORT-fullcheck-ui.md` 末尾追加「第二轮」，并把第一轮 C3、C7 的结论改成如实描述（第一轮修了什么、漏了什么）。
